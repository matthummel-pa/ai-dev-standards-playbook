How it works

Merge to main, and every Claude Code session on every machine picks it up. No manual copying, no stale rules.

What loads when

Every always-on line costs tokens in every session. The playbook keeps one tiny core rule always on and loads everything else only when it's needed.

Rules

Installed to ~/.claude/rules/playbook/. Only core.md is always on; the rest declare paths: and load when Claude reads or edits a matching file.

core.md

Answer first. Branch + small PRs. Read before editing. Sanitize, escape, nonces, capability checks. WCAG 2.1 AA. Never invent metrics. Token discipline. Verify versioned APIs via doc-references.

Loads: every session · must stay under 1 KB

wordpress/wordpress.md

WordPress coding standards, hooks, escaping and query rules.

Paths: **/*.php, theme.json, **/block.json

wordpress/wp-review.md

What a senior WordPress review checks for; used by the wp-reviewer agent and /pb:review.

Paths: **/*.php

sage/sage.md

Sage/Roots conventions: Blade templates, Composers for data, Tailwind v4 tokens, Vite.

Paths: app/**, resources/**, vite.config.js

seo/seo-ai-search.md

AI-search / GEO standards: one intent per page, BLUF, question-style headings, JSON-LD, Core Web Vitals targets.

Paths: **/*.blade.php, **/seo*.php, **/*.mdx

Skills

Installed to ~/.claude/skills/<name>/. Claude sees every description at all times and loads the full body only when the task matches.

doc-references

Canonical reference docs for the whole stack and the rule for verifying against them before coding.

WordPress Developer Resources · Roots / Bedrock · WP Bones environments · Tailwind · MDN · WHATWG HTML · W3C · ARIA APG · web.dev · Modern CSS · caniuse · cssdb · JavaScript.info · TypeScript · React · Next.js · Node · NestJS · Ahrefs · JS/CSS Weekly · Frontend Tools

Use: before touching a hook, class, CSS feature or browser-support question

content-writer

Editorial voice, readability and multi-pass editing for site copy, posts and emails. Adds Editor's Notes when editing someone's writing.

Use: visitor-facing text

growth-design

Growth, CRO, brand design and front-end guardrails as three personas: marketer, graphic designer, web designer.

Use: landing pages, conversion copy, design review

portfolio-seo

Portfolio and service-site SEO: dual audience, skill-first keywords, case-study layout, strict on-page limits.

Use: portfolio, service or project pages

geo-blog-post

Blog posts built for Google AI Overviews and LLM search: BLUF, E-E-A-T proof, FAQ, Article JSON-LD.

Use: writing or outlining a post

sage-architecture

Bespoke Sage/Roots architecture: ACF Pro groups registered in PHP, Customizer dark-mode default, branch hygiene, security, Tailwind/theme.json token bridge, CI/CD for built themes.

Use: ACF fields, Customizer, architecture, deploy workflows

Commands

Namespaced as /pb:… so they never shadow a project's own commands. They load only when typed.

/pb:new-project [slug] [url]

Copies templates/project/ into the current repo without overwriting anything: CLAUDE.md, settings, deploy workflow, setup scripts.

/pb:plan <what>

Plans an L-size change before any code is written.

/pb:fix <what>

Fixes a bug or makes a small change end to end, then ships it.

/pb:review [PR]

Senior WordPress/Sage review of the current branch or a pull request.

/pb:ship

Runs checks, commits, pushes and opens a PR with auto-merge enabled.

Agent & hook

agents/wp-reviewer.md

Senior WordPress/Sage code reviewer. Reviews a diff against the WordPress Developer Handbook and the playbook rules. Tools: Read, Grep, Glob, Bash.

Use: proactively after changing PHP, Blade, JS or CSS, and before a PR

hooks/phpcs-on-edit.sh

PostToolUse hook: runs PHPCS (errors only) on each PHP file Claude edits and sends problems straight back so Claude fixes them before moving on. Warnings are left to wp-review and CI.

Runs: after every Edit / Write of a .php file

Project template

templates/project/ is a drop-in kit for a theme repo. /pb:new-project copies it in. Project facts go in these files; the generic standards stay in the playbook.

CLAUDE.md

Agent brief under 2 KB: stack, how work ships, commands, project facts and hard no's, what to ask first, a pointer to doc-references.

.claude/settings.json

Permissions: allow safe git/gh/npm/composer/phpcs; ask for wp and PR reviews; deny force-push, pushes to main, DB resets, rm -rf, reading .env. WebFetch allowed on every doc-references domain. PHPCS hook wired in.

.github/workflows/deploy.yml

Build on the runner (npm ci && npm run build, composer install --no-dev), upload one complete theme, swap folders over SSH, health-check homepage/REST/CSS, auto-rollback on failure.

tools/ & .github/scripts/

github-setup.sh, hostinger-secrets.sh, pack-theme.sh, server-deploy.sh, health-check.sh.

Ship workflow

The daily loop once a project has the template. Full guide: playbook/automated-ship-workflow.md.

Install

Git Bash (Windows), WSL or macOS. Two minutes, once per machine.

git clone https://github.com/matthummel-pa/ai-dev-standards-playbook.git ~/code/ai-dev-standards-playbook
bash ~/code/ai-dev-standards-playbook/scripts/install.sh

Then in any project:

cd ~/code/my-theme
claude
/pb:new-project my-theme https://example.com

Scripts

ScriptDoes
scripts/install.shCopies the playbook into ~/.claude and adds the SessionStart hook (backup at settings.json.bak-playbook).
scripts/sync.shPulls main and re-copies rules, skills, commands, agents and hooks. Run by the hook; run by hand to apply right away.
scripts/new-project.shCopies the project template into the current repo without overwriting anything.
scripts/validate.pyCI check: frontmatter, core-rule size budget, private-detail scan, CHANGELOG discipline.

Change a rule

  1. Branch. Edit. Add a CHANGELOG.md line; bump VERSION if behavior changes.
  2. Open a PR. validate.yml checks frontmatter, size budgets, private details and shell scripts.
  3. Merge. Every machine picks it up on its next session.

Before adding a rule, read rules-architecture.md. Most new guidance belongs in a skill, not an always-on rule.
